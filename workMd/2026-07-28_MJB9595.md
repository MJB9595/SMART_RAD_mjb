## 1. 작업 목적
- 로컬 환경에서 개발된 애플리케이션을 시놀로지 NAS와 외부 VPS 환경(1GB RAM)에 안정적으로 배포하기 위한 인프라 설정을 구축함.
- 포트 충돌 방지, 메모리 제한 설정, 리버스 프록시 연동, 환경 변수 분리를 통해 배포 유연성을 극대화함.

## 2. 세부 내역 (API 명세, UI 변경점 등)
- **Next.js 리버스 프록시 설정**:
  - `next.config.ts` 파일에 `rewrites` 옵션을 추가하여 프론트엔드로 들어오는 `/api/*` 요청을 백엔드 컨테이너(`http://backend:8080/api/:path*`)로 프록시 전달하도록 수정.
  - 시놀로지 자체 역방향 프록시를 사용하는 경우(Caddy 미사용) 프론트엔드가 백엔드 API 요청을 자연스럽게 넘겨주도록 구조 개편.
- **Docker Compose 설정 개편**:
  - `docker-compose.prod.yml`: 시놀로지 배포를 위해 포트 충돌을 피하고자 `3349`, `8049`, `3049` 포트로 매핑 변경. 각 컨테이너별 메모리 제한(limits)을 추가하여 OOM(Out of Memory) 방지.
  - `docker-compose.vps.yml`: 1GB RAM의 초소형 VPS 배포를 위해 빌드 과정 생략 후 압축된 이미지를 로드하는 방식으로 최적화하고, `caddy` 컨테이너에 `env_file` 설정을 추가해 동적 도메인 할당 구현.
- **환경 변수 분리**: `.env.prod.example` 및 `.env.prod2`를 구성하여 도메인, 카카오 로그인 API 키 등을 런타임에 주입 가능하도록 분리.

## 3. 처리 기준 / 비즈니스 로직
- 프론트엔드 API 호출 URL을 상대경로 `/api`로 통일하고 SSR과 CSR 환경에서의 라우팅 일관성을 확보함.
- Docker 컨테이너 간 통신은 내부망 `8080` 포트를 유지하되, 외부 오픈 포트는 환경에 맞게 `8049` 등으로 동적 변환하여 기존 서비스와의 포트 충돌을 원천 차단함.

## 5. 주요 변경 파일
| 구분 | 파일 | 역할 |
| --- | --- | --- |
| 프론트엔드 | `frontend/next.config.ts` | `/api` 경로를 백엔드 컨테이너로 프록시하기 위한 rewrites 설정 추가 |
| 배포설정 | `docker-compose.prod.yml` | NAS 배포용 서비스 정의, 메모리 제한 및 포트 번호 변경 (`*49`) |
| 배포설정 | `docker-compose.vps.yml` | VPS 배포용 서비스 정의, Caddy 환경변수 로딩 추가 |
| 배포설정 | `.env.prod.example` | 실서버 배포 시 참고할 환경 변수 템플릿 작성 |

## 6. 테스트 및 검증
- 시놀로지 NAS 환경에서 `docker compose up --build` 실행 후 404 에러 원인 파악 및 `next.config.ts` 수정을 통한 정상 로그인 확인.
- 1GB RAM 외부 VPS 환경에서 2GB Swap 설정 및 로컬 빌드 이미지 수동 적재(SCP) 방식으로 OOM 없이 안정적 서비스 기동 확인 완료.
- Caddy를 통한 Let's Encrypt SSL 자동 발급 정상 동작 및 `ERR_SSL_PROTOCOL_ERROR` 해소 확인.

## 7. 기타/후속 연동 지점
- 이후 인프라 변경 시 `.env` 파일의 `DOMAIN` 값과 카카오 설정만 변경하면 프론트 및 백엔드 재빌드 없이 서버 재시작만으로 동적 설정이 적용됨.
