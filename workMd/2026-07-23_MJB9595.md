## 1. 작업 목적
1. **보안 강화 및 환경 설정**: ADMIN 인가를 적용하여 IDOR 취약점을 차단하고 JWT/CORS 환경변수를 통해 운영 환경의 유연성과 보안성을 높입니다.
2. **카카오 소셜 로그인 연동 개선**: 카카오 로그인 시 기존 계정 매칭뿐만 아니라 신규 이메일/미제공 사용자에 대한 대기큐 유입 흐름을 정상화하여 가입 심사 절차를 체계화합니다.
3. **백엔드 견고성 확보**: 낙관적 락(Optimistic Lock) 적용, 404 예외 처리, 승인 스푸핑 방지 등으로 시스템 안정성을 제고합니다.
4. **월근태 및 프론트 연동**: 월근태 집계 API를 구현하고, 5종의 Mock 화면을 실제 데이터 API에 연동하며, 직원 스스로 비밀번호를 변경할 수 있는 UI를 제공합니다.

## 2. 세부 내역 (API 명세, UI 변경점 등)
- **인가 및 경로 설정**:
  - GET `/api/employee/records/*`, `/api/payroll/*`, `/api/attendance/*`, `/api/appointment/*` (클래스 레벨 ADMIN 전용)
  - GET `/api/leave/` 목록/잔여 조회 (비-ADMIN 403 처리)
  - `/api` 이중 접두어 정정 (welfare, allowance, dashboard 등)
- **카카오 회원가입 대기큐 (OAuth)**:
  - 카카오 로그인 시 기존 이메일이 다를 경우 회원가입 승인 대기큐로 유입
  - 이메일 미인증/미제공 사용자라도 카카오 회원번호 기반 식별자를 통해 대기큐 유입 허용
  - `POST /employees/{id}/unmatch`: 잘못 매칭된 계정을 해제하고 신청 대기큐로 복귀시킴
- **셀프 비밀번호 변경**:
  - `PATCH /employees/me/password`: 현재 비밀번호 검증 후 변경 수행
  - 프론트엔드 UI 화면 추가
- **월근태 및 Mock 화면 연동**:
  - 월근태 집계 API 연동 및 프론트엔드 화면 (attendance/monthly 등 5종) 연동 완료

## 3. 처리 기준 / 비즈니스 로직
- **카카오 매칭 로직**:
  - 카카오 계정의 이메일과 기존 시스템 계정의 이메일이 일치하면 자동 연동
  - 불일치 하거나 이메일 미제공 시 카카오 닉네임을 활용해 신규가입 승인 대기큐로 유입 (기존 하드에러 제거)
  - 승인 시 `EmployeeOAuth`를 통해 OAuth 출처 신청 자동 매핑
- **낙관적 락(Optimistic Lock) 처리**:
  - `AuditedEntity.checkOptimisticVersion` 적용
  - `EmployeeUpdate`에 version 파라미터를 추가하여 409 Conflict 반환 (하위호환: version null 시 생략)
- **승인 스푸핑 방지**:
  - Welfare 승인 시 `approverId` 파라미터 제외하고 현재 세션 사용자 기준으로 처리

## 4. 공통 기능 및 보안 (선택 사항)
- **환경 변수 분리**: `JWT_SECRET`, `CORS_ALLOWED_ORIGINS` 환경변수화 (docker-compose 적용)
- **글로벌 예외 처리(GlobalExceptionHandler)**: NoHandlerFound/NoResourceFound → 404, MethodNotSupported → 405 반환으로 불필요한 에러 로그 감소
- **DB 스키마 마이그레이션**: `V5__audit_columns_backfill.sql`을 통한 감사컬럼(created_by/updated_by) 마이그레이션 및 `application.properties`의 `ddl-auto` 값을 `validate`로 변경
