## 1. 작업 목적

월 근태 관리·현황과 급여 관리 데이터를 수작업으로 복사하지 않고 실제 DB 조회 결과를 Excel 통합문서(`.xlsx`)로 내려받을 수 있도록 백엔드 출력 기능을 구현했습니다.

- 월 근태는 직원별 집계와 일별 상세 기록을 한 파일에서 함께 확인할 수 있도록 구성했습니다.
- 급여는 전체 급여대장, 개인별 급여 명세서, 정산 목적별 양식을 각각 제공하도록 분리했습니다.
- 계좌번호 등 민감정보가 포함되는 정산 파일은 기존 관리자 권한 범위 안에서만 생성되도록 유지했습니다.
- 현재 구현 범위는 백엔드 API이며, 프론트엔드 화면의 다운로드 버튼 연결은 포함하지 않습니다.

## 2. 월 근태 엑셀 출력

### API

| 메서드 | 경로 | 파라미터 | 권한 | 결과 |
| --- | --- | --- | --- | --- |
| `GET` | `/attendances/monthly/export` | `year`, `month` | `ADMIN` | 선택 연월의 근태 현황 `.xlsx` |

예시:

```http
GET /attendances/monthly/export?year=2026&month=7
Authorization: Bearer {ADMIN_TOKEN}
```

### 통합문서 구성

#### `월 근태 현황` 시트

직원별 월간 근태 건수를 집계합니다.

| 컬럼 | 내용 |
| --- | --- |
| 사번 / 성명 / 소속 | 직원 식별 및 조직 정보 |
| 출근 / 지각 / 결근 / 연차 | 실제 근태 상태별 건수 |
| 합계 | 상태별 건수 합계(Excel 수식) |

#### `일별 근태 기록` 시트

선택 월의 원본 근태 기록을 날짜 순으로 제공합니다.

| 컬럼 | 내용 |
| --- | --- |
| 근무일 / 요일 | 실제 근무 날짜와 한글 요일 |
| 사번 / 성명 / 소속 | 직원 식별 및 조직 정보 |
| 출근시각 / 퇴근시각 | 등록된 출퇴근 시간, 미등록 값은 빈 셀 |
| 근태상태 | `PRESENT`, `LATE`, `ABSENT`, `ANNUAL_LEAVE`를 한글 상태로 변환 |

### 처리 기준

- 조회 기간은 해당 연월의 1일부터 말일까지 자동 계산합니다.
- 근태 기록은 사번과 근무일 기준으로 정렬합니다.
- 잘못된 연도·월이 전달되면 `400 Bad Request`로 처리합니다.
- 대상 데이터가 없더라도 제목과 헤더를 포함한 정상 통합문서를 생성하고 안내 문구를 기록합니다.

## 3. 급여 엑셀 출력

### API 목록

| 구분 | 메서드 | 경로 | 주요 파라미터 | 결과 |
| --- | --- | --- | --- | --- |
| 전체 급여대장 | `GET` | `/payrolls/export` | 없음 | 전체 급여 목록 |
| 개인 급여 명세서 | `GET` | `/payrolls/{id}/export` | 급여 ID | 선택 급여의 항목별 명세 |
| 정산용 파일 | `GET` | `/payrolls/settlement/export` | `yearMonth`, `formType` | 선택 월·용도별 정산 파일 |

정산 요청 예시:

```http
GET /payrolls/settlement/export?yearMonth=202607&formType=bank
Authorization: Bearer {ADMIN_TOKEN}
```

### 정산 양식 유형

| `formType` | 시트명 | 포함 내용 |
| --- | --- | --- |
| `bank` | `은행 전송용` | 사번, 성명, 은행, 계좌번호, 예금주, 이체금액, 지급일 |
| `acc` | `회계 처리용` | 급여년월, 직원·조직 정보, 총지급액, 총공제액, 실지급액, 상태 |
| `full` | `전체 급여대장` | 급여 정보와 은행·계좌 정보를 포함한 전체 정산 데이터 |

### 급여 처리 기준

- 급여 상태는 DB 기준인 `DRAFT`, `CONFIRMED`, `PAID`를 사용합니다.
- 정산용 파일에는 선택한 급여년월의 `CONFIRMED` 또는 `PAID` 데이터만 포함합니다.
- 급여년월은 `YYYYMM` 형식으로 검증하며 유효하지 않은 값은 `400 Bad Request`로 처리합니다.
- 존재하지 않는 급여 ID의 개인 명세서 요청은 `404 Not Found`로 처리합니다.
- 은행명, 계좌번호, 예금주 필드를 `Employee` 엔티티에 매핑하되 일반 급여 목록 응답에는 추가 노출하지 않았습니다.

## 4. 공통 Excel 생성 규칙

Apache POI `5.5.1`의 OOXML 기능을 사용해 서버에서 통합문서를 생성합니다.

- MIME 타입: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- 한글 파일명: `Content-Disposition`의 RFC 5987 `filename*` 형식으로 UTF-8 인코딩
- 제목 행: 진한 파란색 배경, 흰색 굵은 글씨, 셀 병합
- 헤더 행: 구분색·테두리·가운데 정렬 적용
- 본문: 텍스트·날짜·정수·금액별 셀 형식 분리
- 금액: 숫자 값으로 저장하고 `#,##0"원"` 표시 형식 적용
- 날짜: 실제 날짜 값과 `yyyy-mm-dd` 형식 적용
- 사용성: 헤더 고정, 자동 필터, 명시적 열 너비, 기본 눈금선 숨김
- 호환성: 값이 없는 항목은 빈 문자열 공유 셀이 아닌 실제 빈 셀로 생성
- 수식: 파일 저장 전 계산 및 재계산 플래그 설정

## 5. 보안 및 개인정보 처리

- 근태·급여 컨트롤러의 기존 `@PreAuthorize("hasRole('ADMIN')")` 정책을 그대로 적용합니다.
- 정산 파일 생성 시 계좌정보는 서버 내부에서만 조회하며 일반 급여 조회 DTO에는 포함하지 않습니다.
- `bank`와 `full` 양식은 계좌정보를 포함하므로 관리자만 다운로드할 수 있습니다.
- 다운로드 응답 본문은 JSON 변환 없이 Excel 바이너리로 직접 반환합니다.

## 7. 테스트 및 검증

### 자동 테스트

```bash
./gradlew test \
  --tests com.tphr.hr.attendance.AttendanceExcelServiceTest \
  --tests com.tphr.hr.payroll.PayrollExcelServiceTest \
  --tests com.tphr.hr.ExcelExportControllerTest
```

검증한 항목:

- 월 근태 파일의 2개 시트 생성 및 집계 값 확인
- 급여대장 금액과 상태 값 확인
- 은행 전송용 계좌번호·이체금액 확인
- 개인 명세서, 회계 처리용, 전체 급여대장 엔드포인트 확인
- 관리자 인증이 적용된 실제 컨트롤러 응답의 MIME 타입과 파일 구조 확인
- 생성 파일을 다시 OOXML 통합문서로 열어 시트·행·셀 값 확인

### 시각 검증

실제 시드 데이터로 생성한 근태·급여 파일을 다시 렌더링해 다음을 확인했습니다.

- 제목·헤더·본문 잘림 없음
- 날짜와 금액 표시 형식 정상
- 계좌번호가 숫자로 변환되지 않고 문자열로 유지
- 연차 행의 미등록 출퇴근 시간이 빈 셀로 표시
- `#REF!`, `#DIV/0!`, `#VALUE!`, `#NAME?`, `#N/A` 오류 없음

### 참고 사항

신규 엑셀 단위·통합 테스트는 모두 통과했습니다. 전체 백엔드 테스트 실행 시 기존 `AppointmentApprovalTest`의 관리자 로그인 기대값과 현재 시드 자격 증명이 맞지 않아 로그인 `401` 실패 3건이 별도로 확인됐으며, 엑셀 출력 테스트와는 무관합니다.

## 8. 후속 연동 지점

프론트엔드에서 다운로드 기능을 연결할 때는 기존 JWT를 `Authorization` 헤더에 포함해 위 API를 호출하고, 응답을 `Blob`으로 변환한 뒤 `Content-Disposition` 파일명으로 저장하면 됩니다. 월 근태는 선택된 `year/month`, 급여 정산은 `yearMonth/formType` 값을 그대로 전달해야 합니다.
