## 🧑‍💻 담당자: 김재아 (MJB9595)

### 1. 권한 관리(RBAC)를 실제 인가에 연결
- **내용**: 권한 관리 화면에서 역할의 권한을 바꿔도 아무 변화가 없다는 제보를 추적한 결과, `role`/`permission`/`role_permission`/`employee_role` 4개 테이블이 화면 표시용으로만 존재하고 실제 인가는 `employee.role` 열거값 하나에만 의존하고 있었습니다.
- **결과**: 로그인 시 employee_role → role(active) → permission 을 실제로 읽어 권한을 부여하도록 인증 경로를 재구성하고, `@PreAuthorize` 를 권한 코드 기준으로 전환했습니다. 이제 권한 관리 화면에서 일반직원 역할에 `EMPLOYEE_WRITE` 를 주면 해당 사용자에게 등록·수정 버튼이 곧바로 나타납니다.

### 2. 역할 비활성화 시 접근 차단
- **내용**: 역할을 비활성화해도 해당 계정이 그대로 사용 가능하던 문제를 해결했습니다.
- **결과**: 배정된 역할이 전부 비활성이면 신규 로그인은 물론 **이미 발급된 토큰까지** 403 으로 차단하고 안내 문구를 노출합니다. 다만 역할 배정이 아예 없는 계정은 차단하지 않도록 예외를 둬, 신규 승인 계정이 로그인 불가가 되는 사고를 방지했습니다.

### 3. 타인 명의 대리 신청 취약점 차단
- **내용**: 휴가 신청 API 는 메서드 인가가 아예 없었고, 경조비·증명서와 함께 요청 본문의 `employeeId` 를 그대로 신뢰하고 있어 로그인만 하면 누구나 타인 명의로 신청이 가능했습니다.
- **결과**: 신청 대상자가 본인인지 서버에서 검증하고, 대리 신청은 승인 권한자만 허용하도록 통일했습니다. 일반 계정으로 타인 명의 신청 시 403 이 반환되는 것을 확인했습니다.

### 4. 개인정보 노출 범위 정리 (급여·경조사·증명서)
- **내용**: 경조비·증명서 목록이 전체 조회 방식이라 로그인만 하면 전 직원의 경조사 대상자·가족관계와 증명서 신청 사유가 그대로 보였고, 급여는 `PAYROLL_READ` 권한만 있으면 **전 직원 급여와 전체 급여대장 엑셀까지 실제로 다운로드**되는 상태였습니다.
- **결과**: 권한이 없으면 본인 것만 조회되도록 서버에서 범위를 좁혔고, 전 직원 급여를 담는 급여대장·정산 엑셀은 관리자·인사팀 전용으로 잠갔습니다. 개인 명세서도 본인 것만 내려받을 수 있습니다.

### 5. 월 근태 임의 생성 데이터 제거
- **내용**: 월 근태 관리의 일자별 격자가 `Math.random()` 으로 값을 만들어 내고 있어, 화면에 보이던 출퇴근 시각·지각·연차가 실제 기록과 무관했고 새로고침할 때마다 값이 바뀌었습니다.
- **결과**: 월 집계 응답에 일자별 상세를 담아 실제 근태 기록을 렌더링하도록 교체했습니다. 아울러 급여 상태 코드가 백엔드(`DRAFT/CONFIRMED/PAID`)와 화면(`COMPLETED/PENDING/ERROR`)이 어긋나 "정산 완료" 카드가 항상 0 이던 문제도 함께 바로잡았습니다.

### 6. 전 직원 표본 데이터 시드 및 명단 기준 표시
- **내용**: 월 근태·월 휴가가 기록이 있는 사람만 행으로 만들어, 그 달에 기록이 없으면 본인 행조차 나오지 않았습니다.
- **결과**: 볼 수 있는 명단을 먼저 깔고 그 위에 기록을 얹는 방식으로 바꿔 전원이 행으로 표시되며 본인 행이 강조됩니다. 2026년 7월 평일 전체에 대해 직원 7명의 근태와 휴가 9건을 시드로 넣되, 사람마다 지각·결근·연차 패턴을 다르게 두고 값은 고정해 어느 환경에서도 같은 결과가 나오도록 했습니다.

### 7. 시스템 관리 화면 조작 기능 및 UI 정비
- **내용**: 권한 관리가 조회 전용이라 역할을 만들거나 권한을 바꿀 수 없었고, 공통 코드 관리는 '코드 등록' 버튼이 동작하지 않았으며, 감사로그는 권한 변경이 기록되지 않아 항상 0건이었습니다.
- **결과**: 역할·공통코드 전체 CRUD 를 화면에 연결하고(최고 관리자 역할은 자기 잠금 방지를 위해 보호), 권한·코드 변경을 감사로그에 기록하며 행위자를 이름으로 표시하도록 개선했습니다. 비활성화·삭제는 즉시 반영 대신 '적용' 버튼으로 일괄 처리하도록 바꿨습니다.

### 8. 급여 대장 필터 및 수당 관리 기능 구현
- **내용**: 눌러도 아무 동작이 없던 버튼 3개(발령 필터·내보내기, 급여 필터, 수당 수정)를 확인한 결과 백엔드 API 자체가 없었습니다.
- **결과**: 급여 대장에 급여월·상태·이름/사번 필터를 구현하고(선택지는 실제 데이터에서 추출), 수당의 수정·사용여부 전환·삭제를 추가했습니다. 지급받는 교직원이 있는 수당은 지급 이력 보존을 위해 삭제 대신 비활성을 쓰도록 막았습니다. 발령 엑셀 내보내기는 구현 대상에서 제외하고 버튼을 제거했습니다.

### 9. 소급 등록 정책 정리 (근태·휴가)
- **내용**: 지나간 날짜에 근태·휴가를 사후에 만들어 넣는 것을 막되, 병가처럼 정당한 사후 처리는 가능해야 하는 요구를 반영했습니다.
- **결과**: 일반 직원은 지난 날짜 등록·신청이 서버에서 차단되고(화면에서도 달력 하한·버튼 잠금), 관리자·인사팀만 예외로 소급 처리가 가능합니다. 거부 문구에 "인사팀에 요청하세요"를 넣어 다음 행동을 안내합니다.

### 10. 사용자 피드백 컴포넌트 통합
- **내용**: 브라우저 기본 `alert`/`confirm`/`prompt` 가 41곳에 흩어져 있어 앱 스타일과 따로 놀고 긴 문구를 쓸 수 없었으며, 로드 실패를 콘솔로만 남기는 곳이 20곳이었습니다.
- **결과**: 앱 전역 토스트·확인창·입력창 컴포넌트를 만들어 전부 교체했고, 되돌리기 어려운 조작은 확인 버튼을 빨갛게 구분했습니다. 조용히 삼켜지던 로드 실패도 사유를 화면에 표시하도록 바꿔 "데이터가 없는 것"과 "못 불러온 것"을 구분할 수 있게 했습니다.

### 11. 저장소 정리 및 전 브랜치 동기화
- **내용**: 배포 자동화 스크립트 4개에 대여 서버 접속 정보가 평문으로 커밋돼 있었고, `.gitignore` 에 Java/Gradle 항목이 없어 빌드 캐시가 추적되고 있었습니다.
